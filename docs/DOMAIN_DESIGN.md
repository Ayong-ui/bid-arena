# 领域设计

> 业务规则、数值与验收标准以 [`全栈评测-拍卖间-原文.md`](../全栈评测-拍卖间-原文.md) 为唯一依据。
> 本文件只定义**领域边界、聚合与不变量、一致性边界**，不重复规则。若与原文冲突，以原文为准。

## 1. 模块边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| `auth` | 登录、会话、角色、Agent 凭据校验入口 | 钱包变更 |
| `auction` | 拍卖状态、参与关系、权威快照 | 直接扣款 |
| `bid-command` | 接收、排序、裁决出价命令 | 页面展示 |
| `wallet` / `ledger` | 可用余额、冻结、释放、扣款、流水 | 判断谁赢 |
| `settlement` | 到期/取消后的唯一资金结果 | 接收新出价 |
| `agent` | Token 范围、权限、限流、代理身份 | 绕过竞价服务 |
| `realtime` | 提交后事件、快照恢复 | 作为事实来源 |

**依赖方向**：`bid-command` / `settlement` 依赖 `auction` + `wallet`；`realtime` 只依赖已提交事实；`agent` 复用业务服务，不新增业务规则。

## 2. 聚合与不变量

`Auction` 是竞价聚合根。每场拍卖拥有唯一 `seq`；价格与领先者只能由**同一个出价事务**同时更新。

- `Bid` 是不可变事实记录；`BidRequest` 是幂等入口记录；`Settlement` 每场拍卖最多一条。
- 价格、领先者与结束时间三者必须来自同一次提交，不允许单独漂移。
- 领先者必须是本场参与者。
- 结束时间只在允许出价的进行态存在。
- 钱包两个余额字段及其派生可用额始终非负，且每个变化都有流水。
- 同一用户在同一拍卖的冻结额等于其本场有效出价额。
- 金额一律为整数；ID 在 API 中序列化为字符串。

> 以上是对原文不变量的领域化表述，**不是新规则**；数值与判定条件以原文为准。

## 3. 命令

所有状态变更都建模为带操作者与幂等键的命令：

| 命令 | 操作者 | 幂等键 | 说明 |
|---|---|---|---|
| `START` | 管理员 | 状态条件更新 | 草稿 → 进行态 |
| `BID` | 参与者 / Agent | `(auction_id, user_id, request_id)` | 见 `FUNDING_AND_CONCURRENCY.md` |
| `CANCEL` | 管理员 | 状态条件更新 | 释放本场冻结 |
| `SETTLE` | 系统扫描器 | `settlements.auction_id` 唯一 | 唯一资金结果 |

状态流转与截止判定条件见原文，本文件不复述。

## 4. 两个一致性边界

系统只有两个必须原子完成的边界，其余都是可重试的旁路：

1. **出价事务**：幂等 → 状态/时间/关系/价格/资金校验 → 换庄冻结 → 写流水与出价 → 更新拍卖与 `seq`。
2. **结算事务**：抢占结算态 → 赢家冻结转扣款、他人释放 → 写唯一成交与流水 → 结束态。

两者的锁顺序、幂等记录生命周期与失败分支见 [`FUNDING_AND_CONCURRENCY.md`](FUNDING_AND_CONCURRENCY.md)。

## 5. 读模型

| 读操作 | 形态 | 要点 |
|---|---|---|
| 列表 | 摘要 | 支持按状态过滤与分页 |
| 详情 | 权威快照 | 含状态、价格、匿名领先者、结束时间、延长次数、参与人数、`seq`、`serverTime` |
| 出价历史 | 分页 | 只返回公开字段，不泄露他人钱包 |
| 结算结果 | 单条 | 赢家、成交价、原因；无赢家时也需可读 |

领先者默认匿名化；只有本人与管理员可见需授权的用户信息。快照中的 `seq` 与 `serverTime` 是前端校准与恢复的基线，读模型不参与任何业务判断。
